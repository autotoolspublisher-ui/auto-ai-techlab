DuckDB 2.0「AIエージェント向けモード」を手元で：省略のない15問でバイト54.8%減、トークンは11〜16%減。22問合計のトークンは増えた

分析用データベース DuckDB 2.0 の「AIエージェント向けモード」を、手元の PC で試しました。発表の「AIが読む量を59%減らした」を、TPC-H の22問で、ふつうの表示とエージェント向けの表示を入れ替えて数え直しています。数えたのはバイト・文字と、2つのトークナイザーでのトークン数です。あわせて、モードに入る条件、大きな結果・エラー・見積もりの出方、v1.5.6 とのファイルの互換を見ました。

この回で試したこと

PCIntel Core Ultra 7 265K、Windows
ソフトDuckDB CLI v2.0.0（d54cbbe3df）と v1.5.6（069cc9f9b5）。作業フォルダに置いただけで、PC には入れていない。ライセンスは MIT
データTPC-H の規模1（sf=1）を tpch 拡張で手元で作った（3.69秒、ファイル 280,244,224 バイト）。ダウンロードの合計は約80MB
試し方同じ問いを -agent と -no-agent で1回ずつ。数えたのは標準出力＋標準エラー。すべて 2026-10-26 に1回ずつ
トークンの数え方Ternary Bonsai 2 27B（第2回）と d1-3B（第5回）のトークナイザー（llama-tokenize）。どちらも Claude の数え方とは違う
公式の主張「TPC-H で、エージェント向けモードはモデルが読む DuckDB の出力の量を59%減らした」（発表記事）。規模・問い・数え方（バイトか、トークンか）は書かれていない

結果（実測）

22問の合計・バイト55,926 → 44,334（20.7%減）
22問の合計・文字42,523 → 44,322（4.2%増）
22問の合計・トークンBonsai 18,750 → 27,393（46.1%増）、d1 14,560 → 20,107（38.1%増）
省略のない15問・バイト20,787 → 9,404（54.8%減）
省略のない15問・トークンBonsai 5,901 → 5,243（11.2%減）、d1 4,630 → 3,888（16.0%減）。文字は 13,939 → 9,404（32.5%減）
ふつうの表示の省略7問（2・9・11・16・18・20・21）は、ふつうの表示が40行だけ出して途中を省いていた。エージェント向けは 1,000行・10,000バイトまで全部出す。20問目は Bonsai 1,519 → 6,361 トークン
モードに入る条件Desktop Commander から何も付けずに動かした Claude は、ふつうの表示のまま。実行ファイルから拾った環境変数の名前 11個のうち10個で入った（CURSOR だけでは入らない）。-csv を付ける・DUCKDB_AGENT_MODE=0・-no-agent で切れる
SELECT * FROM lineitem（約600万行）ふつう 16,469 バイト（最初と最後の20行ずつ）、エージェント向け 3,652 バイト（最初の20行と「少なくとも100352行」、問いを途中で止めた）
エラー列名の間違いで、エージェント向けは標準エラーに JSON（種類・候補の列名5つ・位置）。ふつうは文章と場所の印（^^^^）
ファイルの互換v2.0.0 で作ったファイルは v1.5.6 で開けない（version number 69）。v1.5.6 で作ったファイルは v2.0.0 で開けた
費用0ドル（Veo は使っていない。ダウンロードは無料）

わかったこと

  • 省略のない15問では、バイトは54.8%減って公式の59%に近かったが、トークンでは11〜16%減にとどまった。罫線の文字は1文字3バイトだが、トークンではまとまるため
  • 22問の合計ではトークンが増えた（Bonsai 46.1%増、d1 38.1%増）。ふつうの表示が7問で途中を省いていて、エージェント向けは全部出すため
  • 答えが短い問いでは、モードの知らせと見積もりの行が足されて、かえってトークンが増えることがあった（例：6問目 Bonsai 56 → 79）
  • Desktop Commander から動かした Claude はエージェントとは見なされなかった。モードに入るかは環境変数で決まる
  • v2.0.0 で作ったファイルは v1.5.6 で開けなかった

結果の範囲

  • 公式の59%がどの数え方かは分かりません。手元のバイト数（15問で54.8%）は近いですが、同じ数え方かは分かりません
  • Claude など、実際のエージェントのモデルの数え方でのトークン数は数えていません（手元では数えられません）
  • 2つめのトークンの数え方（d1-3B）は、1つめ（Bonsai）の結果を見てから足しました
  • 「省略のない15問」に分けた集計も、結果を見てから決めました（ふつうの表示の「(40 shown)」に気づいたため）
  • 22問の1回目は、非推奨の警告が出力に入ったため、問いの本文を保存して流し直しました。数字は2回目のものです
  • このモードで、エージェントの答えが良くなるか・速くなるかは試していません
  • 各1回の結果です。時間（0.15秒・0.33秒）は比べとして言いません
  • モードに入る環境変数の名前は、実行ファイルの文字列から拾ったものです。これで全部かは分かりません

よくある質問

DuckDB 2.0 のエージェント向けモードで、AIが読む量は59%減りますか？

この回の TPC-H（規模1）では、省略のない15問でバイトは54.8%減りましたが、トークンでは11.2%減（Bonsai）・16.0%減（d1）でした。22問の合計ではトークンが増えました。公式の59%の数え方は分かりません。

22問の合計でトークンが増えたのはなぜですか？

ふつうの表示は7問で途中を省き40行だけ出していましたが、エージェント向けは1,000行・10,000バイトまでは全部出すためです。答えが短い問いでは、モードの知らせと見積もりの行が足されて増えることもありました。

Claude から動かすと自動でエージェント向けモードになりますか？

この回の Desktop Commander から動かした Claude では、ふつうの表示のままでした。CLAUDECODE などの環境変数が設定されていて、出力が端末でなく、出力の形を指定していないときに入ります。DUCKDB_AGENT_MODE=1 だけでも入ります。

v2.0 で作ったファイルは古い版で開けますか？

この回では、v2.0.0 で作ったファイルを v1.5.6 で開けませんでした。v1.5.6 で作ったファイルは v2.0.0 で開けました。
