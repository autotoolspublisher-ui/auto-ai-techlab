llama.cpp 1.0.0（b12359）の新機能、MoE の専門家キャッシュ（--moe-cache-mib）を、RTX 5070 Ti（16GB）の PC で試しました。LFM2.5-8B-A1B（Q4_K_M）の専門家を --cpu-moe で CPU に置き、GPU の置き場の大きさを変えて、書く速さと GPU のメモリを測りました。答えが変わらないかも20問で確かめています。試し方は試す前に保存し、--load-mode none などの条件は結果を見てから足しました。

わかったこと

  • 1.0 の既定（mmap あり）では、置き場 256〜1024MiB がキャッシュなし（59.4）より遅かった（20.2〜39.7）。2048MiB で上回った（78.5、1.32倍）
  • サーバーのログに「--load-mode none を考えて」という警告が --cpu-moe のすべての条件で出ていた。そのとおりに足すと、置き場が小さくてもキャッシュなしより速くなった（256MiB 68.1〜3072MiB 240.2）
  • そのかわり、確保する仮想メモリが約4.6GiB 増え、4096MiB ではこの PC の空きが足りず止めた
  • 専門家の計算を GPU でする限り、キャッシュを使っても20問の答えは全部 GPU と文字まで同じだった。専門家を CPU で計算すると、最初の数十〜数百文字のどこかで言い回しが変わった（例 q14：「brew」と「make」）
  • 同じ設定なら何度聞いても同じだった。前の版と 1.0 は、全部 GPU どうしでも20問すべて文字が違った
  • このモデル（5.16GB）は 16GB の GPU に全部入り、全部 GPU（422.5）が一番速い。今回は試すために、わざと専門家を CPU に置いた

結果の範囲

  • このモデル・この PC・この問いの範囲の結果です。一般化はできません
  • --load-mode none、3072・4096MiB、cpu-share 1、答えの確かめの一部（G2・C2・1024MiB＋--load-mode none）は、結果を見てから足した条件です
  • mmap があるとなぜキャッシュが遅いのか、原因は調べていません。ログの警告どおりにしたら速くなった、までが分かったことです
  • GPU に入りきらない大きなモデルでは試していません
  • 4096MiB＋--load-mode none は止めたため値がなく、その後に予定していた全部 GPU＋--load-mode none は動かしていません
  • 形の判定の正解は 14〜15/20 で違いは1問です。どちらがよいかは、この20問ではいえません
  • 画面の記録で Web UI が表示した速さは、Web UI 自身の設定で送ったもので、上の値とは別です

よくある質問

MoE の専門家キャッシュを使うと速くなりますか？

今回の既定の設定（mmap あり）では、置き場 256〜1024MiB でキャッシュなし（毎秒59.4トークン）より遅くなりました（20.2〜39.7）。2048MiB では 78.5 で上回りました。

遅くならないようにするには？

ログの警告どおり --load-mode none を足すと、256MiB でも 68.1、3072MiB で 240.2 になりました。ただし確保する仮想メモリが約4.6GiB 増え、4096MiB では PC の空きが足りず止めました。

キャッシュを使うと答えは変わりますか？

専門家の計算を GPU でする限り、20問すべてで全部 GPU と文字まで同じでした。専門家を CPU で計算すると言い回しが変わりました。

前の版と比べて速くなりましたか？

全部 GPU で 420.7 → 422.5、--cpu-moe で 58.3 → 59.4 で、ほぼ同じでした。

GPU のメモリはどれだけ減りますか？

全部 GPU の増え 5,395MiB に対し、--cpu-moe だけで 1,027MiB、置き場 1024MiB で 2,051MiB でした。
