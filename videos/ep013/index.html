よくある質問

tsrs は TypeScript の8倍速いですか？

この回の Windows の PC では、発表と同じ条件（同じ checker 数、7.0.2 と比べて）で 2.83〜6.04 倍でした。8倍を超えたのは VS Code を --fast で動かしたときの 8.12 倍だけで、--fast は checker の数を増やす別の設定です。7.1 beta と比べると、同じ checker 数で 2.20〜3.51 倍でした。

tsrs は本家の TypeScript と同じ答えを出しますか？

VS Code、webpack、t3code server、MUI docs の4つでは、7.1 beta と tsrs の標準出力はバイト単位で同じで、終了コードも同じでした。VS Code と webpack の出力ファイル（--checkers 4）も同じでした。4つと20問の範囲の結果で、適合テスト全部を手元で動かしてはいません。

tsrs --fast も同じ答えになりますか？

この4つの標準出力は同じでした。ただし公式の USAGE.md には、--fast は既知のケースで診断の増減や位置・文言の変化、終了コードの変化があると書かれていて、ほかのプロジェクトでも同じとは言えません。出力ファイルは --fast では比べていません。

メモリは70%減りますか？

7.0.2 と比べたワーキングセットのピークで、70%以上減ったのは MUI docs の 80% だけでした（VS Code 62%、webpack 58%、t3code 62%）。7.1 beta と比べると 42〜51% 減です。Windows に確保した量（コミット）で見ると、7.1 beta より webpack で 13% 増え、ほかは 15〜26% 減でした。

Windows や日本語の環境で違いはありますか？

20問のうち15問は一致し、5問が違いました。--locale ja でもメッセージは英語のまま、--watch・--init・--showConfig は未対応で終了コード5、tsconfig も引数もないときは使い方1行だけです。5つとも公式の DEFAULTS.md に書かれていました。日本語のファイル名や Shift_JIS のファイル、260文字を超えるパスなどは一致しました。
