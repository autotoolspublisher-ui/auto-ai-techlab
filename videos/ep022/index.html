第20回の続きです。llama.cpp 1.0（b12359）で、RTX 5070 Ti（16GB）に入りきらない Qwen3.6-35B-A3B（Q4_K_M、20,542,732,576 バイト、約20.5GB）を動かしました。何も付けない起動、専門家を全部 CPU に置く --cpu-moe、新機能の専門家キャッシュ（--moe-cache-mib）、昔からのやり方（--n-cpu-moe で後ろの層の専門家を GPU に置く）を、書く速さと GPU・PC のメモリで比べました。試し方は試す前に保存し、結果を見てから足した条件はそのように書いています。

結果（実測）

何も付けない（D）止めた（読み込み中）。起動から約6.6秒で GPU のメモリが 2,750→15,155MiB、仮想メモリの空きが 12,562→518MiB
--fit-target 4096（D_ft4096、結果を見てから足した）止めた（読み込みの途中で空きが一時 744MiB）。GPU に載せたあとは空き 5,198〜5,238MiB
専門家を全部 CPU（--cpu-moe、C）毎秒 41.3 トークン、GPU のメモリの増え 3,113MiB
C＋キャッシュ2048MiB 35.5（5,147MiB）／4096MiB 50.9（7,195MiB）／8192MiB 82.6（11,291MiB）
昔からのやり方（--n-cpu-moe）後ろの9層を GPU 50.0（6,979MiB）／後ろの18層を GPU 62.1（10,867MiB）
1回目（温まる前）キャッシュ 8.3〜9.7（256トークンに 40〜44秒）、昔からのやり方 28.1〜35.9（9〜11秒）、キャッシュなし 17.3（17.7秒）
20問（K4096、結果を見てから）答えを書けた 10/20、そのうち形の決まりを守れた 10/10、上限で止まり答えが空 10。20問で 491.4秒
20問（K8192）15問目のあとに仮想メモリの空きが 979MiB になり止めた。15問で答えを書けた 8、守れた 8/8、空 7
比べ：第20回の LFM2.5-8B-A1B（全部 GPU）答えを書けた 18/20（うち日本語 9）、守れた 15/18（日本語の9問では 7/9）、29.4秒

わかったこと

  • 20.5GB のモデルは、16GB の GPU でも、専門家を CPU に置けば動いた（毎秒 41.3 トークン）
  • 何も付けないと GPU を 15,155MiB まで使い、仮想メモリの空きが 1GB を切ったので止めた。このPCでは GPU のメモリを使うほど仮想メモリの空きが減る（原因は調べていない）
  • 新機能のキャッシュは、2048MiB ではキャッシュなしより遅かった（35.5 対 41.3）。4096MiB で 50.9、8192MiB で 82.6（キャッシュなしの2.0倍）
  • 同じくらいの GPU のメモリで昔からのやり方と比べると、4GB 相当はほぼ同じ（50.9 対 50.0）、8GB 相当はキャッシュが約1.33倍（82.6 対 62.1）
  • 1回目の問いは、キャッシュの条件が 40〜44秒かかり、昔からのやり方（9〜11秒）より遅かった。キャッシュに専門家が入るまでの間と考えている（推測）
  • 第20回で速くなった --load-mode none は、CPU に置く専門家（約16.9GiB）が仮想メモリの空き（最大 15.2GiB）より大きいため使えない（計算で決め、動かしていない）
  • 20問では、答えを書けた問いは全部、形の決まりを守れた。半分の10問は1024トークンの上限の中で考え終わらず、答えが空だった

結果の範囲

  • このモデル・この PC・この問いの範囲の結果です。一般化はできません
  • --fit-target 4096（D_ft4096）と、20問の K4096 は結果を見てから足した条件です
  • D_ft4096 は読み込みの途中の一時的な減りで止めたもので、止めなければ動いた可能性があります
  • K8192 の20問は15問目で止めたため、20問そろっていません
  • 上限を上げる・考える部分を切る（enable_thinking）は試していません。どちらが賢いかは、この20問・この上限では言えません
  • 仮想メモリの空きが減る原因や、1回目が遅い理由は調べていません
  • 画面の記録で Web UI が送ったものは Web UI 自身のひな形（481トークン）で、上の速さの値とは別です

よくある質問

16GB の GPU で 20.5GB の MoE は動きますか？

専門家を CPU に置く --cpu-moe で動きました（毎秒 41.3 トークン）。何も付けない起動は、仮想メモリの空きが 1GB を切ったので止めました。

新機能の専門家キャッシュは速いですか？

2048MiB では 35.5 で、キャッシュなし（41.3）より遅くなりました。4096MiB で 50.9、8192MiB で 82.6 でした。

昔からのやり方（--n-cpu-moe）と比べると？

同じくらいの GPU のメモリで、4GB 相当は 50.0 対 50.9 でほぼ同じ、8GB 相当は 62.1 対 82.6 でキャッシュが約1.33倍でした。

第20回の --load-mode none は使えますか？

このモデル・このPCでは使えません。CPU に置く専門家（約16.9GiB）が仮想メモリの空きより大きいためで、計算で決めて動かしていません。

答えはちゃんと書けましたか？

20問のうち答えを書けた10問は、すべて形の決まりを守れました。残りの10問は1024トークンの上限の中で考え終わらず、答えが空でした。
